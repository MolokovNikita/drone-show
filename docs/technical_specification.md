# Техническое задание
## Система управления световыми шоу дронов

---

## 1. Введение

### 1.1. Назначение документа
Настоящее техническое задание описывает требования к разработке полнофункциональной информационной системы для управления световыми шоу дронов. Система предназначена для автоматизации процессов планирования, выполнения и мониторинга световых шоу с использованием беспилотных летательных аппаратов.

### 1.2. Область применения
Система применяется в организациях, занимающихся организацией и проведением световых шоу с использованием дронов для развлекательных, рекламных и культурных мероприятий.

### 1.3. Термины и определения
- **Дрон** - беспилотный летательный аппарат, оборудованный светодиодными модулями
- **Шоу** - запланированное световое представление с участием группы дронов
- **Хореография** - последовательность движений и формаций дронов во время шоу
- **Телеметрия** - данные о состоянии дрона в реальном времени
- **Алерт** - уведомление о критическом событии или состоянии системы

## 5. Архитектура системы

### 5.1. Общая архитектура
Система построена по архитектуре **Frontend → REST API → Business Logic → Data Layer → PostgreSQL**

**Компоненты:**
- **Frontend**: React 18 приложение с Material UI
- **Backend API**: Node.js + Express сервер
- **WebSocket Server**: Отдельный сервер для телеметрии
- **Database**: PostgreSQL
- **Authentication**: JWT токены

### 5.2. Слои приложения

#### 5.2.1. Presentation Layer (Frontend)
- React компоненты
- Redux для управления состоянием
- Material UI для интерфейса
- Three.js для 3D визуализации
- Recharts для графиков

#### 5.2.2. API Layer (Backend)
- Express.js роутеры
- Контроллеры для обработки запросов
- Middleware для аутентификации и валидации
- Swagger для документации API

#### 5.2.3. Business Logic Layer
- Сервисы для бизнес-логики
- Валидация данных
- Обработка ошибок
- Генерация алертов

#### 5.2.4. Data Access Layer
- Sequelize ORM
- Модели данных
- Миграции базы данных
- Seed данные

### 5.3. Коммуникация
- **HTTP/REST**: Для всех CRUD операций
- **WebSocket**: Для телеметрии в реальном времени
- **JWT**: Для аутентификации

## 8. API

### 8.1. REST API Endpoints

#### Аутентификация
- `POST /api/auth/register` - Регистрация
- `POST /api/auth/login` - Вход
- `POST /api/auth/refresh` - Обновление токена
- `GET /api/auth/profile` - Профиль пользователя

#### Дроны
- `GET /api/drones` - Список дронов
- `GET /api/drones/:id` - Детали дрона
- `POST /api/drones` - Создание дрона
- `PUT /api/drones/:id` - Обновление дрона
- `DELETE /api/drones/:id` - Удаление дрона

#### Шоу
- `GET /api/shows` - Список шоу
- `GET /api/shows/:id` - Детали шоу
- `POST /api/shows` - Создание шоу
- `PUT /api/shows/:id` - Обновление шоу
- `DELETE /api/shows/:id` - Удаление шоу

#### Проекты
- `GET /api/projects` - Список проектов
- `GET /api/projects/:id` - Детали проекта
- `POST /api/projects` - Создание проекта
- `PUT /api/projects/:id` - Обновление проекта
- `DELETE /api/projects/:id` - Удаление проекта

#### Телеметрия
- `GET /api/telemetry` - Список телеметрии
- `GET /api/telemetry/latest/:droneId` - Последняя телеметрия дрона
- `GET /api/telemetry/stats` - Статистика телеметрии
- `POST /api/telemetry` - Создание записи телеметрии

#### Алерты
- `GET /api/alerts` - Список алертов
- `POST /api/alerts/:id/acknowledge` - Подтверждение алерта
- `POST /api/alerts/:id/resolve` - Решение алерта

### 8.2. WebSocket API
- `ws://localhost:3002` - Подключение к WebSocket серверу
- Формат сообщений: JSON
- События: telemetry, alerts, connected, disconnected

### 8.3. Документация API
- Swagger UI доступен по адресу `/api-docs`
- OpenAPI 3.0 спецификация в `/docs/swagger.json`

## 11. Последовательности процессов

### 11.1. Процесс авторизации
1. Пользователь вводит credentials
2. Frontend отправляет запрос на `/api/auth/login`
3. Backend проверяет credentials в БД
4. Backend генерирует JWT токены
5. Frontend сохраняет токены
6. Frontend перенаправляет на главную страницу

### 11.2. Процесс получения телеметрии
1. Дрон отправляет телеметрию через WebSocket
2. WebSocket сервер валидирует данные
3. WebSocket сервер сохраняет данные в БД
4. WebSocket сервер проверяет условия для алертов
5. WebSocket сервер рассылает данные всем подключенным клиентам
6. Frontend обновляет UI с новыми данными

### 11.3. Процесс создания шоу
1. Менеджер создает проект
2. Менеджер создает шоу в рамках проекта
3. Менеджер назначает дроны на шоу
4. Хореограф создает хореографию
5. Хореограф определяет траектории и формации
6. Система проверяет готовность дронов
7. Шоу готово к выполнению
